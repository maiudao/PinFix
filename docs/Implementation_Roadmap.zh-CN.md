# PinFix 三步实施文档

## 总体策略

PinFix 不应该第一天就做成很大的浏览器扩展。更稳的路线是先做油猴脚本，验证核心流程真的好用，再决定是否升级成 Chrome 或 Edge 扩展。

三步路线：

1. MVP：能点选、能标注、能写备注、能复制文字、能进入截图准备。
2. Polish：当前窗口导出、样式设置、暗亮页面适配、自动保存更完善。
3. Extension Ready：为未来浏览器扩展做准备，增强截图能力和项目化导出。

## 第一步：MVP 核心可用版

目标：先让用户能真正用它给 Codex 提需求。

必须完成：

- 油猴脚本基础结构。
- 左侧中间 PinFix 启动按钮。
- 标注模式开关。
- 5 个主工具入口：选择、样式、截图、复制、更多。
- 鼠标悬停高亮网页模块。
- 点击模块生成标注框。
- 自动生成编号。
- 每个标注有备注输入框。
- 输入框支持回车换行。
- 输入框失焦后自动保存并折叠。
- 鼠标悬停或编辑时展开备注。
- 页面底部补充说明区。
- 复制结构化文字。
- 截图准备模式，隐藏工具栏，保留标注框和编号。
- 保存用户最近一次使用的颜色、粗细、标签样式和语言。
- 基础亮色/暗色页面显示策略。
- 清空当前页面标注。
- 简体中文和英文界面基础支持。

第一步暂不做：

- 自动截图。
- 长图截图。
- 复杂样式面板。
- 项目包导出。
- 云端同步。

验收标准：

- 用户可以在一个真实网页上标出 3 到 5 个修改点。
- 每个修改点能写说明，并且刷新后不会丢。
- 点击“复制文字”后，可以直接粘贴给 Codex。
- 点击“截图准备”后，用户可以用 Windows 截图，且工具栏不会入镜。
- 再次打开 PinFix 时，能沿用上次样式和语言。
- 插件按钮不会严重挡住页面。

建议文件结构：

```text
PinFix/
  README.md
  docs/
  src/
    pinfix.user.js
    modules/
      i18n.js
      toolbar.js
      selector.js
      overlay.js
      notes.js
      storage.js
      exportText.js
```

备注：

- 如果第一版为了安装方便，也可以先把代码合成一个 `pinfix.user.js`。
- 即使合成单文件，也要按模块区域写清楚注释。

## 第二步：体验完善版

目标：让它更像一个精致工具，而不是临时脚本。

必须完成：

- 截图准备模式。
- 点击后隐藏工具栏和输入框 5 秒。
- 保留标注框和编号，方便 Windows 手动截图。
- 当前可见区域截图导出。
- 导出截图前自动隐藏 PinFix 控件。
- 如果复制图片失败，则自动下载 PNG。
- 颜色预设：红、蓝、绿、黑白。
- 框线粗细：细、中、粗。
- 标签大小设置。
- 设置面板和更多菜单。
- 样式浮层、截图浮层和更多浮层。
- 撤销上一步。
- 删除单个标注，不弹确认，误删用撤销恢复。
- 扩大选区和缩小选区。
- 候选框右上角快捷按钮：缩小、扩大、普通标注、遮挡。
- 键盘快捷键。
- 更完善的英文界面。

第二步重点细节：

- 截图时不能把工具栏、设置面板、备注输入框拍进去。
- 备注输入框只在编辑和悬停时展开。
- 标注编号在浅色和深色背景上都要清晰，必须有双层描边或反差描边。
- 靠近屏幕边缘时，框线、编号标签和按钮要自动收进可见区域。
- 工具栏按钮要有 tooltip，不能让用户猜。
- 左侧关闭按钮默认隐藏，鼠标移入工具栏或键盘聚焦时出现。
- 可见主按钮最多 5 个，低频功能必须收进浮层。
- 所有设置修改后自动保存，不要求用户手动点保存。
- 动效要有质感，但必须支持减少动态效果。

验收标准：

- 用户可以完成“标注、写说明、截图准备、复制文字”的完整流程。
- 用户可以只通过候选框右上角按钮完成缩小、扩大、标注和遮挡。
- 用户手动截图时，画面里只有网页、框线和编号。
- 页面刷新后，标注和备注能恢复。
- 页面刷新后，颜色、粗细、语言和截图倒计时等设置能恢复。
- 中英文切换后，主要界面文字都能正确显示。

## 第三步：扩展准备版

目标：如果油猴版被频繁使用，就为正式浏览器扩展做准备。

可以增加：

- Chrome 或 Edge 扩展版本。
- 更稳定的浏览器原生截图能力。
- 真实当前标签页截图。
- 标注项目导出为 zip。
- 一键生成 `notes.md` 和 `screenshot.png`。
- 多页面标注管理。
- 给每个标注记录更准确的页面元素路径。
- 更好的隐私遮挡工具。
- 更完善的开源文档和贡献指南。

这一阶段再考虑：

- 是否支持长图。
- 是否支持云端同步。
- 是否支持团队评论。
- 是否支持和 GitHub Issue、Linear、Notion 等工具对接。

验收标准：

- 扩展版截图比油猴版更稳定。
- 用户可以导出完整资料包。
- 项目结构适合开源协作。
- 文档足够让其他人安装、试用、贡献。

## 开发顺序建议

建议按这个顺序开发：

1. 语言字典和基础样式。
2. 左侧启动按钮和工具栏。
3. 设置保存和默认模式恢复。
4. 模块选择和高亮。
5. 标注框和编号。
6. 备注输入框。
7. 本地保存。
8. 复制文字。
9. 底部补充说明。
10. 截图准备模式。
11. 当前可见区域截图导出。
12. 样式浮层、截图浮层、更多浮层。
13. 打磨中英文 README 和开源说明。

## 每一步都要做的检查

每完成一个小功能，都要检查：

- 页面是否还能正常点击和滚动。
- PinFix 是否能退出标注模式。
- 标注是否会挡住关键内容。
- 刷新后数据是否符合预期。
- 刷新后用户设置是否能恢复。
- 亮色和暗色页面下标注是否都清楚。
- 中英文文字是否来自语言字典。
- 代码里是否有必要注释。

## 手动验证页面建议

第一版至少在这些页面类型上试用：

- 普通商品页。
- 后台表单页。
- 卡片列表页。
- 长内容文章页。
- 有固定顶部导航的页面。

不用一开始做全网兼容。先保证在用户自己的项目页面上好用。
